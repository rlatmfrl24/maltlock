# 몰트락 통합 수집 UI 구현·검증 기록

## 결과와 실제 진입 흐름

공통 사이트 선택 아래에 수집결과 / 크롤링 두 탭을 제공한다. 기본 화면은 수집결과이며 사이트 선택은 브라우저를 이동하지 않는다. 크롤링 시작에서 설정된 사이트 URL 이동 → 새 문서 확인 → 기존 파싱·저장 → 누적 수집결과 표시로 이어진다. 성공, 중복만 발견, 일부 완료, 실패, 중지 모두 결과 화면과 정확한 실행 요약으로 종료된다.

밝은 배경과 기존 녹색 강조색, 3×2 사이트 선택, 큰 비율 유지 썸네일, 좁은 패널의 독립 목록 스크롤을 적용했다. 600px 이상은 두 열이다. 키보드 탭 이동과 결과 제목 포커스 복귀, 로딩·빈 결과·읽기 오류 상태를 제공한다. 수집 중에는 사이트·설정·삭제 변경을 잠근다.

## 검증 근거

- 기준 단위 테스트: 22개 파일, 140개 통과.
- 리뷰 수정 후 `pnpm.cmd check`: 타입 검사, ESLint, 단위 테스트 25개 파일·155개, Vite 빌드 통과.
- `cfcb997` 빌드의 전체 Playwright: 일반 E2E 18개 통과, 선택 실행인 실제 사이트 테스트 1개 제외. 사이트 선택, 새 문서 준비, 수동 이동 보존, 중지·타임아웃, 자동 수집, 중복·일부 완료, 삭제·캐시·좁은 패널을 검증했다.
- 추가 해시 회귀: 수정 전 실제 확장 UI가 기존 문서 ID를 재사용하는 실패를 관찰했다. 수정 후 해시 추가·변경·동일 주소 재실행 모두 새 문서 ID로 수집·저장하는 E2E가 통과했다. 수정 빌드의 시작 버튼 E2E도 다시 통과했다.
- 실제 NimiWiki: `about:blank`에서 사이트 선택 → 크롤링 탭 → 시작으로 네 플랫폼을 순회했다. 실제 API 응답과 IndexedDB 항목을 비교했고 각각 100건, 총 400건이 저장됐다. 예상 항목 누락은 0건이었다. 실제 썸네일을 로드하고 400×600 화면을 확인했다.
- 실제 블루스카이 링크는 웹 플레이어를 열었고 재생 시간이 증가했다. 다운로드는 발생하지 않았다. 삭제 후 항목 수 감소, seen 로그 유지, 다음 삭제 버튼의 키보드 포커스를 확인했다.
- 최종 `8a5ac32` 빌드에서 시작 버튼과 세 가지 해시 E2E 2개가 통과했다. 실제 NimiWiki를 재실행하여 네 플랫폼 총 400건과 `success`인 실행 기록 네 개를 IndexedDB에서 읽었다. 기록의 신규 저장 합계는 저장 항목 수 400건과 일치했다. 플레이어·썸네일·삭제 검증도 다시 통과했다.

## 독립 리뷰와 수정

한 명의 새 리뷰어가 `ae112de..cfcb997` 전체를 읽기 전용으로 검토했다. Critical 0, Important 1, Minor 0이었다. P2 해시 URL 문제는 실제 Chromium과 확장 UI에서 재현됐다. 설정 URL에 해시를 추가하면 이전 문서가 유지됐는데도 수집 성공으로 처리됐다.

이 판단을 수용하여 해시를 제외한 같은 문서 주소에서도 이전 문서 ID를 확인한다. 목표 주소가 적용됐지만 문서가 그대로인 경우 한 번 reload하고 새 문서 ID가 준비된 뒤 진행한다. 실제 Chrome에서 해시가 포함된 완전히 동일한 주소를 다시 여는 경우도 문서가 유지되어 reload 대상에 포함했다. 수동 이동 검사와 취소 검사를 유지했다. 단위 회귀 실패 → 세 주소 변형을 포함한 아홉 개 테스트 통과, 실제 UI의 동일 문서 실패 → 새 문서 확인 E2E 통과로 이어졌다.

추가 검증에서 임시 프로필의 워커 시작 타임아웃이 간헐적으로 발생했다. 시작한 동일 빌드에서는 수동 이동·중지·타임아웃 등 영향 범위 여덟 개가 통과했다. 새 반복 UI 테스트의 설정 펼침을 매번 토글하여 닫던 테스트 오류는 현재 펼침 상태를 읽어 수정했다. 최종 해시·시작 버튼 검증 두 개가 모두 통과했다. 워커 시작의 환경 변동은 제품 동작의 성공 근거로 사용하지 않았다.

## 구현 판단과 비용

- 대화에서 승인한 설계를 저장한 spec을 기준으로 실행했다. 비용은 문서 관리뿐이다.
- 준비 문서와 UI 소비자를 한 커밋으로 전달했다. 서로 필요한 인터페이스가 중간 단계에서 깨지는 것을 방지하며 리뷰 범위만 커진다.
- 자동 수집은 준비된 `tabId/documentId`를 받고 첫 문서를 재사용한다. 추가 reload를 줄이고 다른 활성 탭으로 바뀌는 것을 방지한다. 세 종류 수집기의 회귀로 검증했다.
- 종료 시 NimiWiki 출처 필터를 전체로 되돌려 완료 결과를 보이게 한다. 선택 항목은 유지하며 사용자는 필요할 때 필터를 다시 선택한다.
- `CANCEL_TARGET_SITE/requestId`로 준비 취소를 워커에 전달한다. UI 대기만 취소하면 늦은 탭 이동이 발생할 수 있어 런타임과 UI 회귀를 함께 추가했다.
- 이전 현재 페이지 옵션 테스트는 승인된 설정 URL의 단일 페이지 흐름으로 변경했고, 자동 수집의 초기 사이트 이동을 방문 횟수에 포함했다. 기존 구현을 유지하기 위해 제품 의도를 재해석하지 않았다.
- E2E마다 임시 프로필을 사용했다. 오래된 워커 상태를 피하고 같은 실행 안의 패널 재접속은 기존 DB·캐시를 유지한다. 비용은 브라우저 시작 시간이다.
- 이미지 레이아웃 fixture에는 확장 아이콘 응답을 제공했다. 존재하지 않는 이미지 호스트와 이전 테스트의 캐시 의존을 제거했으며 실제 원격 썸네일은 별도 실제 수집에서 검증했다.
- 해시만 바뀐 같은 문서에는 reload를 보장한다. 해당 조건에서 한 번의 페이지 로드 비용이 발생한다.

## 검증 범위와 남은 작업

새 의존성, DB 마이그레이션, 검색·정렬은 범위에 넣지 않았다. 기존 파서와 저장·중복·사생활·삭제 계약을 유지했다. 필수 기능을 fixture나 하위 API 진입으로 대체하지 않았으며 fixture는 회귀 검증에만 사용했다. 새 데이터 경로와 실제 사이트 실행에서 권한·진입·저장 의미의 역전은 확인되지 않았다.

다른 다섯 사이트의 현재 접속·로그인·외부 파서 정확성은 실사이트에서 재검증하지 않았다. 개인 Chrome에 설치된 확장의 reload는 브라우저 제어 정책으로 수행하지 못했다. 원본 `dist`를 빌드한 뒤 사용자가 확장을 새로고침해야 기존 설치에서 변경을 사용할 수 있다. push·PR·merge는 수행하지 않으며 로컬 브랜치와 작업 트리는 복구용으로 보존한다.

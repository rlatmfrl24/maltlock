# NimiWiki 썸네일 로딩 지연 원인과 수정

## 확인한 원인

기준 master는 `18ff338b39141042ac1a453db6b7732b857486be`다. 실제 확장의 시작 버튼으로 NimiWiki 네 플랫폼 400건 저장은 완료됐지만, 보이는 블루스카이 썸네일은 15초 안에 로드되지 않는 경우가 재현됐다.

기존 컴포넌트는 원격 URL을 img에 넣고 모든 마운트된 행에서 캐시용 fetch도 실행했다. img의 lazy loading은 별도 fetch를 제한하지 않았다. 크롤링 중 숨겨진 결과 목록에서도 이미지 요청이 발생했으며, 같은 URL의 fetch와 native image 요청이 중복됐다.

실제 실패 응답에는 `HTTP 428`, `cdn-limit: true`, `server: BunnyCDN-LA1-954`가 있었다. 이는 이 실행에서 CDN의 요청 제한이 발생했다는 근거다. HTTP 428 자체를 일반적인 속도 제한 코드로 해석하지 않는다. 첫 이미지가 로드된 기준 실행에서도 블루스카이 fetch 100건과 HTTP 428 응답 52건을 관찰했다.

## 수정과 보존한 계약

- 화면과 가까운 행만 IntersectionObserver로 로드한다. 숨겨진 결과나 먼 스크롤 위치에서는 요청하지 않는다.
- 원격 다운로드는 캐시 helper 한 경로로 처리하고 검증된 Blob을 표시한다. 목록에서 벗어나거나 컴포넌트가 사라지면 진행 중 요청을 취소하며, 다시 보이면 요청을 재개한다. 네트워크 대기는 10초로 제한한다.
- 캐시 사용 불가·쓰기 실패가 유효한 이미지의 표시를 막지 않는다. 다운로드 완료 후 저장은 비동기로 처리하되 항목별 순서와 삭제 후 캐시 제거를 보장한다.
- 실패했던 URL에서 다른 URL로 바뀌었다가 다시 돌아오면 이전 실패 상태를 버리고 다시 로드한다.
- 파서·저장 URL·DB·확장 권한은 변경하지 않았다. 응답 상태·MIME·빈 Blob 검증, credentials omit, no-referrer, 기존 캐시 복구와 삭제 계약을 유지했다.

- 기준 `pnpm.cmd check`: 170건 통과.
- 수정 전 숨겨진 목록 40행의 요청 0건 기대가 실제 40건으로 실패했다. 취소를 제거한 mutation에서도 스크롤 후 취소 이벤트 검증이 실패했다. 수정 후 숨겨진 요청 0건, 스크롤 취소·재진입·픽셀 표시·캐시 저장을 확인했다.

- 독립 리뷰 Important 2건(캐시 쓰기가 표시를 막음, URL 복귀 시 오래된 실패 재사용)을 수정했다. 재리뷰에서 추가 지적은 없었다.
- 리뷰 수정 후 `pnpm.cmd check`: 타입·ESLint·26개 파일의 단위 테스트 175건·Vite 빌드 통과. 최종 UI 번들은 `sidepanel.html-is7t9KEF.js`다.

- 실제 웹 플레이어 재생 시간 증가·다운로드 없음, 삭제 후 항목 제거·seen 로그 유지·다음 삭제 버튼 포커스도 두 주소에서 확인했다. 재접속 회귀는 원격 호스트를 막은 뒤 캐시 Blob으로 복원했다.
